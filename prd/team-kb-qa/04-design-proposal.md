# v0.2 设计方案：现代 AI 知识工作台

日期：2026-07-07

## 1. 目标

本阶段目标不是继续美化现有验证页，而是把 `Team Wiki` 设计成一个现代 AI 产品感的团队知识工作台。

新的前端项目命名为：

- `team-wiki-react-ui`

旧前端保留：

- team-wiki-vue-ui 已废弃并删除。

当前临时新前端：

- `team-kb-qa-ui` 可作为功能验证参考，但下一阶段建议用 React 重做。

## 2. 产品气质

关键词：

- 现代 AI 产品
- 私有知识工作台
- 专业、安静、可信
- 比传统后台更轻，比聊天工具更有结构

不采用：

- 营销落地页风格
- 大面积装饰性渐变
- 普通企业后台模板感
- 只做一个聊天框的验证页

核心体验应该让用户明确感知：

- 当前正在使用哪个知识库
- 当前知识库是否完成索引
- 回答来自哪些文档
- 当前用户有哪些权限
- 模型和 Agent 当前处于什么配置

## 3. 用户角色

### 普通用户

普通用户的核心任务是：

- 选择自己有权限的知识库
- 基于知识库发起问答
- 查看历史会话
- 查看回答来源
- 判断回答是否可信

普通用户不应该被管理配置打扰。

### 管理员

管理员的核心任务是：

- 配置多个知识库
- 观察索引状态
- 管理用户和授权范围
- 配置模型
- 后续配置 Agent
- 查看使用量和系统状态

管理员需要更高信息密度，但仍应保持现代产品的清爽感。

## 4. 信息架构

### 一级导航

建议采用左侧主导航：

- `Ask`：知识库问答
- `Knowledge`：知识库管理
- `People`：用户和权限
- `Models`：模型配置
- `Agents`：Agent 配置，第一版可占位
- `Insights`：用量和运行状态
- `Settings`：系统设置，第一版可弱化

普通用户只显示：

- `Ask`

管理员显示全部导航。

### Ask 页面

布局建议：

```text
┌──────────────────────────────────────────────────────────────┐
│ Top bar: 当前知识库 / 索引状态 / 模型 / 用户                 │
├───────────────┬──────────────────────────────┬───────────────┤
│ 会话列表       │ 问答主区域                    │ 上下文面板      │
│               │                              │               │
│ - 知识库切换   │ - 欢迎态                      │ - 知识库状态    │
│ - 新会话       │ - 对话流                      │ - 来源引用      │
│ - 历史会话     │ - 输入框                      │ - 命中文档      │
│               │                              │ - 工具过程      │
└───────────────┴──────────────────────────────┴───────────────┘
```

重点：

- 知识库切换必须非常显眼。
- 切换知识库后，会话列表也随之切换。
- 回答区域必须显示来源，不只显示自然语言文本。
- 如果知识库未索引完成，输入框应显示明确状态。

### Knowledge 页面

管理员使用。

功能：

- 知识库列表
- 新增知识库
- 编辑名称、路径、启用状态
- 查看索引文件数
- 查看索引时间
- 查看索引错误
- 手动重建索引，后续实现

建议呈现：

- 顶部统计条
- 中间表格
- 右侧或弹窗编辑表单

### People 页面

管理员使用。

功能：

- 用户列表
- 新增用户
- 启用 / 停用用户
- 修改角色
- 修改知识库授权
- 重置密码

权限编辑建议使用：

- 用户详情抽屉
- 多选知识库授权
- 明确显示管理员默认拥有全部知识库

### Models 页面

管理员使用。

功能：

- 模型配置列表
- 新增模型
- 设置默认模型
- API Key 配置
- 启用 / 停用模型
- 简单连通性测试，后续实现

模型配置需要显示：

- Provider 名称
- Base URL
- Model
- 是否默认
- 是否配置 Key
- 最近更新时间

### Insights 页面

第一版可以做基础仪表盘。

指标：

- 用户数
- 启用知识库数
- 启用模型数
- 今日问答次数，后续实现
- token 估算量，后续聚合
- 索引健康状态

## 5. 视觉系统

### 色彩

建议使用多色但克制的 B2B AI 产品色彩：

- 背景：`#F6F8FB`
- 面板：`#FFFFFF`
- 主文本：`#101828`
- 次文本：`#667085`
- 边框：`#D9E2EC`
- 主色：`#0F766E` 或 `#2563EB`
- 成功：`#16A34A`
- 警告：`#D97706`
- 错误：`#DC2626`

避免：

- 全页面蓝紫渐变
- 单一蓝灰配色铺满
- 过度圆角和厚阴影

### 圆角和密度

- 普通卡片：8px
- 按钮：6px 或 8px
- 输入框：6px 或 8px
- 页面区块不要卡片套卡片
- 管理页保持较高信息密度
- 问答页允许更舒展

### 字体层级

- 页面标题：20-24px
- 区块标题：15-17px
- 正文：14px
- 辅助信息：12-13px

不要使用巨大的 hero 字号。

## 6. 关键交互

### 知识库切换

切换知识库时必须同步：

- 当前知识库状态
- 会话列表
- 问答上下文
- 右侧来源面板

如果指定知识库未索引，应阻止提问，并提示管理员检查配置。

### 来源引用

回答完成后，应展示：

- 来源文档标题
- 文档路径
- 命中片段
- 来源顺序或相关度

这需要后端提供结构化 sources，而不是只依赖模型在回答里自然语言引用。

### 工具调用

工具调用不应该默认打扰普通用户。

建议：

- 默认折叠
- 用一个小标签显示“检索 3 次”
- 点击后在右侧上下文面板查看详情

### 空态

空态应该帮助用户开始提问，而不是介绍系统功能。

建议提供：

- 本知识库概览
- 推荐问题
- 最近文档，后续实现

### 错误态

必须区分：

- 没有知识库权限
- 知识库未索引
- 模型未配置
- 模型调用失败
- 后端连接失败

## 7. React 技术方案

建议技术栈：

- React
- Vite
- TypeScript
- Tailwind CSS
- shadcn/ui
- Radix UI
- lucide-react
- TanStack Query
- Zustand 或 React Context
- react-markdown 或 marked

目录：

```text
team-wiki-react-ui/
├── package.json
├── index.html
├── vite.config.ts
├── tailwind.config.ts
├── src/
│   ├── app/
│   ├── components/
│   │   ├── ui/
│   │   ├── layout/
│   │   ├── chat/
│   │   └── admin/
│   ├── features/
│   │   ├── auth/
│   │   ├── chat/
│   │   ├── vaults/
│   │   ├── users/
│   │   ├── models/
│   │   └── insights/
│   ├── lib/
│   │   ├── api.ts
│   │   ├── sse.ts
│   │   └── format.ts
│   └── main.tsx
```

### 为什么换 React

原因：

- `team-kb-qa-ui` 是新前端，迁移成本低。
- shadcn/ui + Tailwind 更适合快速建立现代 AI 产品设计语言。
- TanStack Query 更适合管理后台和多页面数据状态。
- React 生态在 AI SaaS 产品 UI 上更成熟。

## 8. 后端需要继续补的接口

为了让设计真正成立，后端需要补充：

### 知识库状态

```text
GET /api/vaults/:id/status
```

返回：

- 是否索引中
- 文件数
- 最近更新时间
- 错误信息
- vaultPath

### 来源引用

```text
POST /api/chat
```

`done` 事件建议增加：

- `sources`
- `vaultId`
- `model`

source 格式建议：

```json
{
  "title": "部署指南",
  "path": "部署指南.md",
  "snippet": "命中的内容片段",
  "score": 0.82
}
```

### 用量统计

```text
GET /api/admin/usage/summary
```

返回：

- 今日问答次数
- 7 日问答次数
- token 估算
- 用户排行
- 知识库排行

### 索引操作

```text
POST /api/admin/vaults/:id/reindex
```

用于手动重建索引。

## 9. 分阶段计划

### Phase 1：React 骨架和视觉系统

目标：

- 创建 `team-wiki-react-ui`
- 接入登录
- 接入 `/api/me`
- 建立主导航、布局、主题、基础组件
- 不急着覆盖所有功能

验收：

- 登录后能进入工作台
- 普通用户和管理员导航不同
- 页面视觉接近现代 AI 工作台

### Phase 2：Ask 页面

目标：

- 知识库切换
- 会话列表
- SSE 问答
- 右侧上下文面板
- 错误态和空态

验收：

- 切换知识库不会串库
- 未索引知识库不能提问
- 回答完成后能看到来源区域占位

### Phase 3：管理员配置

目标：

- Knowledge 页面
- People 页面
- Models 页面
- Insights 基础仪表盘

验收：

- 管理员可完成 P0 的配置闭环
- 新增知识库后能看到索引状态变化
- 用户授权变更后普通用户可见范围变化

### Phase 4：可信回答增强

目标：

- 后端结构化 sources
- 前端来源引用组件
- 工具过程折叠展示
- 用量统计聚合

验收：

- 回答可追溯
- 管理员能看到基础使用情况

## 10. 当前功能不足

现阶段已发现并需要设计层解决的问题：

- 页面仍偏验证工具，不像完整产品。
- 知识库索引状态没有被充分展示。
- 回答来源缺少结构化展示。
- 管理配置和普通问答没有清晰分区。
- 模型配置缺少测试能力。
- Agent 配置还只是 PRD 中的预留项。
- 用量统计只有事件写入，没有聚合展示。

## 11. 设计结论

下一步建议不要继续扩展 `team-kb-qa-ui`。

建议新建：

- `team-wiki-react-ui`

并以现代 AI 知识工作台为目标，从布局和设计系统开始重做。

第一版先追求：

- 清晰的信息架构
- 明确的知识库边界
- 可信的问答体验
- 管理员配置闭环

后续再增强：

- 来源引用
- 索引操作
- 用量统计
- Agent 配置
- 审计和 SSO
